# TTL/DLX цепочка retry-очередей вместо delayed-message-exchange плагина

RabbitMQ redelivery (`nack` + requeue) не имеет встроенной задержки, а ТЗ требует экспоненциальный backoff. Вместо плагина `rabbitmq_delayed_message_exchange` реализована цепочка из трёх retry-очередей с TTL (2с / 8с / 32с) — каждая через `x-dead-letter-exchange` возвращает сообщение в основную очередь `payments.new` по истечении TTL. Номер попытки читается из длины `x-death` header. После 3-й неудачной попытки сообщение уходит в финальную `payments.new.dlq`.

Решение не требует стороннего плагина (которого нет в официальном образе `rabbitmq:management` из коробки) и явно демонстрирует ручную работу с обменниками/очередями/bindings — один из критериев оценки ТЗ. Плата — 4 дополнительные очереди вместо одного delayed-exchange.
