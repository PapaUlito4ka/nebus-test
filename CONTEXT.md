# Payments Processing

Микросервис, принимающий запросы на оплату, обрабатывающий их через эмулируемый внешний платёжный шлюз и уведомляющий вызывающую сторону о результате через webhook.

## Language

**Payment**:
Денежная операция, запрошенная через `POST /api/v1/payments`: хранит сумму, валюту, статус и данные для уведомления о результате.
_Avoid_: Transaction, Order

**Idempotency-Key**:
Ключ, переданный клиентом в заголовке при создании платежа, однозначно определяющий повторную попытку того же запроса. Совпадающее тело с уже виденным ключом — replay существующего платежа; отличающееся тело — конфликт (409).
_Avoid_: Request ID, Dedup key

**Outbox**:
Таблица, в которую запись о новом платеже и событие для очереди пишутся в одной транзакции. Гарантирует, что событие `payments.new` не потеряется, даже если процесс упадёт сразу после коммита.
_Avoid_: Event log — это конкретно outbox-таблица, не общий журнал событий

**Outbox relay**:
Фоновая задача внутри API-процесса, вычитывающая неотправленные записи из Outbox и публикующая их в очередь `payments.new`. См. [ADR-0002](docs/adr/0002-outbox-relay-in-process.md).
_Avoid_: Publisher worker, relay service — в этом проекте это не отдельный сервис

**Gateway emulation**:
Имитация внешнего платёжного шлюза внутри Consumer: задержка 2-5 сек, затем случайный терминальный исход (90% succeeded / 10% failed). Исход не переигрывается при повторной доставке сообщения.
_Avoid_: Payment gateway — в системе нет настоящего внешнего шлюза, только эмуляция

**Consumer**:
Единственный обработчик сообщений из `payments.new`: идемпотентно проверяет текущий статус платежа, при необходимости выполняет Gateway emulation, обновляет статус в БД и отправляет Webhook notification. При повторной доставке не переигрывает Gateway emulation, если платёж уже в терминальном статусе — повторяет только отправку webhook. См. [ADR-0001](docs/adr/0001-unified-retry-via-broker-redelivery.md).
_Avoid_: Worker, handler — в контексте этого проекта конкретно Consumer

**Webhook notification**:
HTTP-уведомление о результате платежа, отправляемое Consumer на `webhook_url`, указанный при создании платежа. Доставляется вызывающей стороне API, а не плательщику.
_Avoid_: Callback

**Retry queue chain**:
Три промежуточные очереди (`payments.retry.1/2/3`) с нарастающим TTL (2с/8с/32с), через которые проходит сообщение между неудачными попытками Consumer — обеспечивает экспоненциальную задержку без стороннего плагина RabbitMQ. См. [ADR-0003](docs/adr/0003-ttl-retry-chain.md).
_Avoid_: Delay queue — в проекте это конкретно цепочка TTL-очередей, не общий механизм задержки

**Dead Letter Queue (DLQ)**:
Финальная очередь для сообщений `payments.new`, которые не удалось обработать — включая неудачную отправку Webhook notification — после того как Retry queue chain исчерпана (3 попытки).
_Avoid_: Error queue, retry queue — последнее теперь означает конкретно Retry queue chain
